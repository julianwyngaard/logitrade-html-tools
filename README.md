# tools.julianwyngaard.dev

A collection of single-file HTML tools hosted at [tools.julianwyngaard.dev](https://tools.julianwyngaard.dev).

Inspired by [Simon Willison's tools](https://tools.simonwillison.net/) and his [blog post on building HTML tools](https://simonwillison.net/2025/Dec/10/html-tools/).

## Philosophy

Each tool is a **standalone HTML file** with inline JavaScript and tool-specific CSS, sharing one small stylesheet (`tools.css`). This means:

- **No build step** for the tools themselves
- **CDN dependencies** - external libraries loaded from CDNs when needed
- **Client-side only** - no server required, all processing happens in the browser
- **URL state** - every tool stores its state in the URL for sharing
- **Consistent chrome** - the same header, toolbar, status box, and footer on every tool

## Tools

See [index.html](https://tools.julianwyngaard.dev) for the full, generated list, and the [colophon](https://tools.julianwyngaard.dev/colophon.html) for each tool's history.

## Quick Start

```bash
# Clone the repo
git clone https://github.com/julianwyngaard/logitrade-html-tools.git
cd logitrade-html-tools

# Build the index and colophon pages
npm run build

# Serve locally for testing
npx serve . -l 3737
# Then open http://localhost:3737
```

No dependencies to install - the build scripts use only Node.js built-in modules.

## Adding a New Tool

The full checklist, required functionality, and conventions live in **[AGENTS.md](AGENTS.md)**; the visual system lives in **[STYLE.md](STYLE.md)**. In short:

1. Copy `docs/tool-template.html` to `[slug].html` and build the tool inside it.
2. Write `[slug].docs.md` (structure in AGENTS.md).
3. Add an entry to `tools.json`:

   ```json
   {
     "slug": "tool-name",
     "name": "Tool Name",
     "description": "One sentence for the index page. Shareable via URL.",
     "category": "data",
     "created": "2026-01-18",
     "updated": "2026-01-18"
   }
   ```

   Categories: `data`, `networking`, `image`, `dev`, `misc` (or add a new one - see below).
4. `npm run build`, verify in the browser, then commit `[slug].html`, `[slug].docs.md`, `tools.json`, `index.html`, and `colophon.html` on a `feature/[slug]` branch and open a PR.

## Build System

The build system generates two pages from `tools.json`:

### index.html

The main tool listing page, organized by category. Generated by `scripts/build-index.js`.

### colophon.html

A "behind the scenes" page showing each tool's description (from `.docs.md` files) and git commit history. Generated by `scripts/build-colophon.js`. Because it embeds the git log, rebuild it on every commit that touches a tool.

### npm scripts

| Command | Description |
|---------|-------------|
| `npm run build` | Run all build scripts |
| `npm run build:index` | Regenerate only index.html |
| `npm run build:colophon` | Regenerate only colophon.html |
| `npm run serve` | Start local dev server on port 3000 (prefer `npx serve . -l 3737`) |

## tools.json Reference

```json
{
  "tools": [
    {
      "slug": "tool-name",        // URL-safe identifier (matches filename)
      "name": "Tool Name",        // Display name
      "description": "...",       // One sentence for the index, ending "Shareable via URL."
      "category": "data",         // Category key
      "created": "2026-01-18",    // ISO date, never changes
      "updated": "2026-01-18"     // ISO date (bump when the tool changes)
    }
  ],
  "categories": {
    "data":       { "name": "Data & Text",    "order": 1 },
    "networking": { "name": "Networking",     "order": 2 },
    "image":      { "name": "Image & Media",  "order": 3 },
    "dev":        { "name": "Development",    "order": 4 },
    "misc":       { "name": "Miscellaneous",  "order": 99 }
  }
}
```

To add a new category, just add it to the `categories` object with a unique key, display name, and order.

## Deployment

Deployment is automatic via GitHub Actions:

1. Push to `main` branch
2. GitHub Actions runs `npm run build`
3. Generated files are deployed to GitHub Pages

The workflow uses `fetch-depth: 0` to get full git history, which the colophon generator needs for commit history.

## Design Principles

Based on [Simon Willison's guidance](https://simonwillison.net/2025/Dec/10/html-tools/):

1. **Single-file tools** - Each tool is one HTML file with inline JS and tool-specific CSS
2. **No build step for tools** - Tools work by just opening the HTML file
3. **CDN for dependencies** - Use CDN links instead of npm packages
4. **URL state** - Store shareable state in URL parameters
5. **localStorage for secrets** - Keep API keys client-side only
6. **Client-side processing** - No server needed, privacy-preserving
7. **Keep it small** - Aim for a few hundred lines per tool
