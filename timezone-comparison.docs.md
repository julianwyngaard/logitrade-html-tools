# Timezone Comparison

Compare working hours across timezones to find a meeting slot that works for everyone. Everything runs client-side — no server, no tracking.

## Features

- Side-by-side hour strips, one per place, all aligned to the same moment
- Search by city or country (e.g. "Portland", "Tokyo", "India", "New York") against a broad built-in list — your own timezone is added automatically
- The place keeps the name you searched for, even where several cities share one timezone (Portland stays "Portland", not "Los Angeles"), and that name travels with the share link
- Click any hour to select a meeting time and see it instantly in every timezone; hovering a column previews it everywhere
- Keyboard accessible: tab to the "Overlap" bar, then use arrow keys / Home / End to move the selection
- Hours are shaded like a heat-map: green for working hours, amber for outside-hours-but-still-awake (early morning / evening), grey for night; the "Overlap" bar highlights hours when everyone is within working hours, and says so when no such hour exists
- A day chip (e.g. "-1 day") flags places on a different calendar day, a subtle divider marks each place's local midnight, and a marker shows the current hour
- Zones offset by 30 or 45 minutes (India, Nepal, Adelaide) show their real local time, e.g. `9:30`
- Adjustable working hours — including overnight windows such as 22:00–06:00 — and meeting date
- The place-name column stays pinned while the hour strip scrolls sideways
- Shareable URLs with the full comparison embedded
- Remembers your last setup, including custom place names, via localStorage

## How to Use

1. Your local timezone appears first, alongside two common hubs to start
2. Search for a city or country and click it to add another timezone
3. Pick the meeting date and your working-hours window
4. Click any hour in any strip — the selected time updates everywhere, with the exact local time and date per place
5. Look for the green band in the "Overlap" bar: those hours fall within working hours for everyone
6. Click **Share link** to copy a URL that reproduces the exact comparison for others

## URL Parameters

- `?zones=Europe/London,America/New_York` — comma-separated IANA timezones (first is the anchor); duplicates and unknown zones are dropped
- `?names=London%2C%20UK|New%20York%2C%20USA` — pipe-separated display names, positionally matched to `zones`
- `?date=YYYY-MM-DD` — the meeting date; invalid values fall back to today
- `?t=14` — selected **column index**, counting from the start of the anchor day. This equals the local hour on ordinary days, but not on daylight-saving transition days, when the day has 23 or 25 columns
- `?w=9-17` — working-hours window (start–end, 24-hour). `start > end` means an overnight window, e.g. `22-6`

## Technical Details

- Uses the browser's built-in `Intl.DateTimeFormat` for all conversions, so daylight saving transitions are handled automatically for the chosen date
- Columns are generated by walking real hours from the anchor day's first instant to the next day's, so a spring-forward day has 23 columns and a fall-back day has 25 — a fixed 24 would drop or duplicate an hour
- Where clocks go back and the same wall-clock hour happens twice, both columns are tagged with the zone abbreviation (`1 EDT` / `1 EST`) so the two are distinguishable
- Handles zones where local midnight does not exist because DST starts at 00:00 (Santiago, Beirut, Cuba) by anchoring to the first hour that does
- Falls back to UTC when the host reports an unmappable timezone (`Etc/Unknown`), rather than failing to start
- Working-hour classification uses fractional local hours, so `:30` and `:45` offset zones are grouped correctly
- Timezone search ranks name matches above keyword matches and shows one entry per zone
- XSS-safe rendering: place names go through `textContent`, and the one `innerHTML` site (the summary banner) is escaped
- State priority: URL parameters > localStorage > sensible defaults (your zone + New York + London)
